## 今日高危漏洞

### 1. CVE-2026-84939 — Apache FreeMarker 模板路径遍历漏洞

Apache FreeMarker 模板加载机制存在路径遍历漏洞。当攻击者能够指定任意模板路径时，可读取服务器上任意文件，可能导致敏感配置泄露（数据库凭据、密钥等），进而实现进一步攻击。CVSS 9.1，属于严重级别。

- **CVSS**：9.1
- **影响组件**：Apache FreeMarker（模板引擎，Java 生态广泛使用）
- **与当前栈关联**：高度相关。多乐士 CMS 基于 Spring Boot，若使用 FreeMarker 作为视图模板引擎且模板路径可控，则存在被路径遍历攻击的风险。需排查项目中是否引入了 FreeMarker 依赖及模板路径是否受用户输入影响。

### 2. CVE-2026-57967 — Apache ActiveMQ Artemis 会话劫持漏洞

未认证的远程攻击者可通过构造 CORE 协议 SESSION_REATTACH 数据包窃取现有会话并冒充已认证用户，导致消息队列完全失控。CVSS 9.8，严重级别。

- **CVSS**：9.8
- **影响组件**：Apache ActiveMQ Artemis（消息中间件）
- **与当前栈关联**：潜在相关。若多乐士 CMS 后端使用了 ActiveMQ Artemis 作为消息队列（Spring Boot 集成中较常见），需立即排查。若未使用 ActiveMQ 组件则无影响。

### 3. CVE-2026-49364 — Apache ActiveMQ Artemis 集群凭据捕获漏洞

未认证的网络邻接攻击者可通过发现机制在集群通信过程中捕获管理凭据，进而获取队列管理权限。CVSS 9.1。

- **CVSS**：9.1
- **影响组件**：Apache ActiveMQ Artemis
- **与当前栈关联**：同上，取决于是否使用 ActiveMQ Artemis。若使用且部署了集群模式，风险更高。

### 4. CVE-2026-67593 — Apache ActiveMQ Artemis 队列删除漏洞

远程攻击者可通过构造 Openwire RemoveSubscriptionInfo 命令删除 Artemis Broker 上的队列，导致消息丢失和服务中断。CVSS 9.1。

- **CVSS**：9.1
- **影响组件**：Apache ActiveMQ Artemis
- **与当前栈关联**：同上。

### 5. CVE-2026-49362 — Apache ActiveMQ Artemis 未授权队列创建漏洞

未认证的远程攻击者可通过 CORE 协议创建任意持久化队列，导致资源耗尽和未授权消息写入。CVSS 7.5。

- **CVSS**：7.5
- **影响组件**：Apache ActiveMQ Artemis
- **与当前栈关联**：同上。

### 6. CVE-2026-49363 — Apache ActiveMQ Artemis 集群节点信息泄露漏洞

未认证的远程攻击者可通过 CORE 协议 SUBSCRIBE 命令发现集群节点详情，为后续攻击提供信息。CVSS 7.5。

- **CVSS**：7.5
- **影响组件**：Apache ActiveMQ Artemis
- **与当前栈关联**：同上。

### 7. CVE-2026-19583 — Velociraptor 敏感 Artifacts 权限绕过漏洞

Velociraptor（开源数字取证工具）允许部分敏感 artifacts 绕过额外权限检查，可能导致未授权访问系统信息。CVSS 9.9。

- **CVSS**：9.9
- **影响组件**：Velociraptor（DFIR 工具）
- **与当前栈关联**：无直接关联。当前栈未使用 Velociraptor，但若安全团队使用该工具需注意升级。

### 8. CVE-2026-87491 — Google Chromium V8 越界写入漏洞（CISA KEV）

Google Chromium V8 引擎存在越界写入漏洞，已确认被在野利用。攻击者可通过恶意网页内容触发堆损坏并执行任意代码。

- **CVSS**：未在 NVD 数据中标注（CISA KEV 已收录）
- **影响组件**：Google Chromium V8 引擎
- **与当前栈关联**：间接相关。Node.js 运行时基于 V8 引擎，但 Node.js 通常使用 LTS 版本的 V8，与 Chromium 版本不同步。若本机或服务器运行了基于 Chromium 的浏览器或 Electron 应用，需关注更新。多乐士 CMS 前端的 Next.js 服务端运行在 Node.js 上，但 V8 漏洞利用需要浏览器环境，Node.js 服务端风险较低。

## 建议动作

**立即处理：**
1. 排查多乐士 CMS 项目是否引入了 Apache FreeMarker 依赖（检查 pom.xml 中的 freemarker 相关 artifact），确认模板路径是否受外部输入控制。若使用了 FreeMarker 且版本受影响，需立即升级到修复版本。
2. 排查多乐士 CMS 是否使用了 Apache ActiveMQ Artemis 作为消息中间件（检查 pom.xml 和 Spring Boot 配置中的 spring.activemq 或 artemis 相关配置）。若使用，需立即升级到修复版本，并确认 Broker 端口（默认 61616）未暴露在公网。

- Dropbox 数据泄露事件后续进展，确认是否有企业数据涉及
