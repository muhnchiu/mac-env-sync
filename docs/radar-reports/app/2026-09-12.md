## 今日最值得关注

### 1. Raycast 2.0 发布（Product Hunt）

Raycast 推出 2.0 大版本更新，作为 macOS 上最受欢迎的第三方启动器，新版本重构了扩展系统、AI 集成和窗口管理。Product Hunt 今日榜热度第一。

- **Cask**：`raycast`（官方 cask，brew install --cask raycast）
- **价值判断**：启动器是高频入口工具，Raycast 免费版已覆盖 Alfred 大部分核心功能且生态更活跃；2.0 是重要节点。
- **与台账关联**：台账中 Alfred 5 为三机在用的手动装启动器。Raycast 免费且扩展生态更现代，可考虑作为 Alfred 的替代或互补。

### 2. Cline Desktop App（Product Hunt）

Cline 推出独立桌面客户端，将原来 VS Code 扩展形态的 AI 编程助手拆出为原生 app，支持多编辑器场景。

- **Cask**：暂无独立 cask，当前为官网下载 dmg。
- **价值判断**：AI 编程工具从编辑器插件走向独立客户端是趋势，Cline 开源免费且支持多模型，对不想被单一编辑器绑定的开发者有吸引力。
- **与台账关联**：台账中 VS Code Insiders 为主力编辑器，Claude/ChatGPT 为独立 AI 客户端。Cline Desktop 与现有 AI 客户端定位不同，是编程专用而非通用对话。

### 3. Rune 开源（HN 首页 134 分）

Rune 是一个现代构建工具，此前为商业产品，现在正式开源。HN 社区关注度较高。

- **Cask**：无（Rust 生态工具，cargo install 或 npm）。
- **价值判断**：构建工具开源对开发者社区是好事，但当前项目生态和适用场景需要进一步评估，不适合立刻收编。
- **与台账关联**：台账无直接重叠。开发工具链以编辑器+终端为主，构建工具属于项目级依赖，不作为系统基线。

### 4. Litelm：轻量 LiteLLM 替代（HN 首页 89 分）

Litelm 是 LiteLLM 的精简实现，目标是去掉 LiteLLM 的臃肿依赖，提供轻量的多 LLM API 代理。

- **Cask**：无（Python 包，pip install litelm）。
- **价值判断**：多模型路由工具在 AI 开发中越来越重要，轻量化方向值得跟踪。但当前 star 数和成熟度还不够，观察为主。
- **与台账关联**：台账中无 LLM 代理类工具。如果后续需要在本地做多模型切换，可作为基础设施候选。

### 5. MSSH：5MB 单文件 SSH 客户端（小众软件）

面向开发者与运维的轻量桌面 SSH 终端，支持多会话、SFTP、快捷键，体验接近 Xshell。配置完全本地，开箱即用。

- **Cask**：无（官网下载，macOS/Windows 双平台）。
- **价值判断**：5MB 极致轻量是亮点，但功能与 Termius/iTerm2 重叠。Termius 有云同步、iTerm2 有丰富生态，MSSH 的差异化在于"零配置即用"，适合临时场景或辅机。
- **与台账关联**：台账中 SSH 工具有 Termius（core，云同步）、iTerm2（手动装）、Transmit（堡垒机专用）、WindTerm（p14）。MSSH 与 Termius 重叠度高，不建议收编。

### 6. gpty：Godot+Rust 终端多路复用器（HN Show HN 76 分）

基于 Godot 引擎和 Rust 编写的终端多路复用器，支持面板分割等功能，是一个实验性项目。

- **Cask**：无（GitHub 开源，需编译）。
- **价值判断**：用 Godot 做终端是有趣的技术探索，但作为日常终端工具成熟度不足。跟踪观察即可。
- **与台账关联**：台账中主力终端为 Ghostty，iTerm2 为备选。gpty 与现有终端工具定位不同（多路复用而非终端模拟），更接近 tmux 的竞品。

### 7. Konode：浏览器同步工具（小众软件）

号称理想中的浏览器同步工具，支持标签页、扩展、浏览历史、书签、密码、Cookie 等数据的跨浏览器同步，不依赖 Chrome 自带同步。

- **Cask**：无（官网下载）。
- **价值判断**：跨浏览器同步是真实痛点（Chrome 同步在国内受限，Edge 同步有账号问题）。如果 Konode 能稳定运行且支持本地优先，有实用价值。但需考察其安全模型（Cookie/密码同步涉及敏感数据）。
- **与台账关联**：台账中 Chrome 和 Edge 均为核心浏览器。Konode 不替代浏览器本身，但可作为同步层补充。安全风险需评估后再决定。

### 8. UPDF AI Agent：AI 直接改 PDF（小众软件）

UPDF 在 PDF 编辑器中内嵌 AI Agent，选中文字可直接调用 AI 编辑功能，将 AI Agent 概念引入 PDF 编辑场景。

- **Cask**：`updf`（可能存在，需验证；UPDF 官网提供 dmg 下载）。
- **价值判断**：AI+PDF 编辑是有意思的方向，但 UPDF 是商业软件（免费版有限制），且台账中无 PDF 编辑器需求。
- **与台账关联**：台账中无专门 PDF 编辑器（WPS/Keynote 可处理部分需求）。如果未来有 PDF 编辑高频需求可考虑，当前不需要。

### 9. Claude Read Aloud（HN Show HN）

开源项目，让 Claude 的回复可以被朗读出来，替代阅读长文本。

- **Cask**：无（GitHub 项目，需自行部署）。
- **价值判断**：无障碍和效率场景有用，但功能单一。OpenClaw 已有 TTS 能力（tts 工具），对当前工作流无增量。
- **与台账关联**：台账中无直接重叠。TTS 能力已由 OpenClaw 内置 tts 工具覆盖。

### 10. Graphify C#：为编码代理提供编译器级 Find Usages（HN Show HN）

开源工具，为 AI 编码代理提供精确的代码引用查找，比 LLM 猜测的引用更准确。

- **Cask**：无（GitHub 开源，C#/dotnet 生态）。
- **价值判断**：提升 AI 编码准确性的基础设施工具，方向正确。但绑定 C# 生态，适用范围有限。
- **与台账关联**：台账中 AI 工具有 Claude/ChatGPT/Codex++。Graphify 是辅助层而非独立工具，当前项目以 Java/前端为主，C# 适用性不高。

## 建议动作

**立即试用：**
1. Raycast 2.0 -- 在 mini 上 brew install --cask raycast 安装试用，与 Alfred 5 并行运行一周，评估是否替换。Raycast 免费版功能覆盖率高，扩展生态活跃，是 Alfred 的有力替代。
2. Konode -- 官网下载试用，重点验证跨浏览器同步稳定性及安全模型（Cookie/密码同步的可信度）。若安全可控，可解决 Chrome/Edge 跨浏览器同步长期痛点。

**跟踪观察：**
- Cline Desktop App -- 关注其多编辑器支持进展和开源社区活跃度，若成熟度提升可替代部分 Claude/ChatGPT 的编程辅助场景。
- Litelm -- 跟踪 star 数和功能完善度，轻量 LLM 代理在多模型场景有潜力。
- gpty -- 实验性项目，关注其终端多路复用功能的成熟度，看是否能与 Ghostty 形成互补。

**收藏：**
- Rune 开源 -- 构建工具开源信息归档，项目有需要时再评估。
- Graphify C# -- 编译器级代码引用查找思路值得学习，若未来有 C# 项目可启用。

**不收编：** MSSH（SSH 工具已饱和，无增量价值）、UPDF AI（台账无 PDF 编辑器需求且为商业软件）、Claude Read Aloud（TTS 已有内置方案）、StartPad（Windows 平台与台账无关）。
